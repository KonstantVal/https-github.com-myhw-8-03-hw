### Задание 1 Резервное копирование
Кейс

Финансовая компания решила увеличить надёжность работы баз данных и их резервного копирования.

Необходимо описать, какие варианты резервного копирования подходят в случаях:

1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день.

1.2. Необходимо восстанавливать данные за час до предполагаемой поломки.

1.3.* Возможен ли кейс, когда при поломке базы происходило моментальное переключение на работающую или починенную базу данных.

Приведите ответ в свободной форме.

### Решение 1

1.1 Лучше всего использовать полное резервное копирование. Это самый простой и распространенный вариант. 
Полная резервная копия создает полную копию базы данных на определенный момент времени. 
Это позволяет легко восстановить всю базу данных до состояния, в котором она была в предыдущий день.

1.2 Хорошим вариантом может стать инкрементное резервное копирование. Этот вариант идеально подходит для частого восстановления данных, поскольку он фиксирует изменения небольшими порциями.

1.3 Такой кейс возможен в случае зеркалирования базы данных. Это подразумевает создание реплики первичной базы данных в реальном времени на отдельном сервере. Если первичная база данных выходит из строя, зеркальный сервер может немедленно взять на себя управление, обеспечивая минимальное время простоя. Ресурсоемкое решение.

### Задание 2 PostgreSQL

2.1. С помощью официальной документации приведите пример команды резервирования данных и восстановления БД (pgdump/pgrestore).

2.1.* Возможно ли автоматизировать этот процесс? Если да, то как?

Приведите ответ в свободной форме.

### Решение 2

2.1 Резервное копирование:

pg_dump -h localhost -p 5432 -U postgres -d mydatabase > mydatabase_backup.sql

Эта команда создаст резервную копию базы данных с именем «mydatabase» на локальном хосте, используя порт 5432 и пользователя postgres. Резервная копия будет сохранена в файле «mydatabase_backup.sql».

Восстановление:

pg_restore -h localhost -p 5432 -U postgres -d mydatabase -F p -c mydatabase_backup.sql

Эта команда восстановит базу данных из файла «mydatabase_backup.sql». Она подключится к локальному хосту, порт 5432, используя пользователя postgres, и восстановит данные в базе данных «mydatabase».

2.1.* Да, можно автоматизировать процесс резервного копирования и восстановления с помощью скриптинга.

Можно написать скрипты на таких языках, как Python, Bash или других скриптовых языках, чтобы автоматизировать процесс резервного копирования и восстановления. Эти скрипты могут включать логику для обработки различных сценариев, таких как управление файлами, обработка ошибок и системы уведомлений.

### Задание 3 MySQL

3.1. С помощью официальной документации приведите пример команды инкрементного резервного копирования базы данных MySQL.

3.1.* В каких случаях использование реплики будет давать преимущество по сравнению с обычным резервным копированием?

Приведите ответ в свободной форме.

### Решение 3

3.1 mysqldump -u user -p --single-transaction --master-data=2 --events --databases database_name > database_name_incremental_backup.sql

Эта команда создаст инкрементную резервную копию базы данных с именем «database_name».

3.1.* Преимущества использования реплики перед обычным резервным копированием:

Доступность данных в режиме, близком к реальному времени: реплики можно настроить так, чтобы они были копиями первичной базы данных в режиме, близком к реальному времени, что позволяет быстрее восстанавливаться в случае сбоя.

Минимальное время простоя: в случае сбоя основной базы данных вы можете быстро переключиться на реплику, что сводит к минимуму перерывы в обслуживании.

Операции только для чтения: реплики могут обрабатывать операции только для чтения, что позволяет разгрузить трафик чтения с основного сервера и повысить производительность.

Восстановление на определенный момент времени: с помощью реплик можно вернуться к определенному моменту времени, что обеспечивает более детальное восстановление.
